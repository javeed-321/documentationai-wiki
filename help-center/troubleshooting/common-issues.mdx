## Common Issues

Use the sections below to identify your symptom, understand the likely cause, and apply the step-by-step fix. Each expandable contains a complete resolution path.

<Expandable title="Broken article links after publishing" default-open="false">

Problem: Visitors click an article link and receive a 404 page even though the article appears in the help center.

Cause: The article slug changed during an edit or the link was created with an outdated ID before the article was republished.

Fix: Open the article in the Zendesk admin interface, copy the current URL from the preview pane, and replace every instance of the old link in other articles or theme files. Then republish the affected pages. Run a site-wide search for the old slug in the content editor to catch any remaining references.

</Expandable>

<Expandable title="Missing search results for recently published articles" default-open="false">

Problem: New articles do not appear in help center search even 24 hours after publication.

Cause: Search indexing has stalled, often shown by the message "Indexing in progress" that never completes in the admin dashboard.

Fix: In Zendesk Admin, go to Help Center then Settings and click Rebuild search index. Wait for the confirmation email, then test the article title in the public search bar. If results still fail to appear, verify the article is set to Published and that no label restrictions block it from the default search scope.

</Expandable>

<Expandable title="Custom theme CSS not rendering correctly" default-open="false">

Problem: Custom styles appear broken on the live help center while the preview in the theme editor looks correct.

Cause: A syntax error in the stylesheet or a missing asset reference prevents the compiled CSS from loading.

Fix: Open the theme editor, switch to the CSS tab, and look for unclosed braces or invalid color values. Replace any `url()` references with full paths that begin with `https://example.com`. Click Preview, then Publish once the live site matches the preview. Clear your browser cache or test in an incognito window to confirm the update.

</Expandable>

<Expandable title="SSO login failures with redirect errors" default-open="false">

Problem: Users attempting single sign-on see the message "Unable to authenticate with the identity provider" and are returned to the login screen.

Cause: The SSO redirect URI registered in Zendesk does not match the callback URL configured in your identity provider.

Fix: In Zendesk Admin under Settings then Security, copy the exact SSO callback URL listed under your SSO provider. Paste that URL into the allowed redirect list in your identity provider console. Save both sides, then test the login flow again from a fresh browser session.

</Expandable>
