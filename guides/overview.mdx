## Overview

Trigger.dev lets you build and run long-running background jobs in TypeScript. You define tasks that handle API calls, webhooks, scheduled work, and AI workloads. The platform manages retries, queues, and visibility so you can focus on business logic.

Core capabilities include durable scheduled tasks, fine-grained concurrency controls, realtime connections from your frontend, and complete tracing across every run.

## Scheduled Tasks

Scheduled tasks run on durable cron schedules that survive restarts and timeouts. You register a schedule once and Trigger.dev keeps it active.

```typescript
import { schedules } from "@trigger.dev/sdk/v3";

export const dailyReport = schedules.task({
  id: "daily-report",
  cron: "0 9 * * *",
  run: async (payload) => {
    // fetch data and send report
  },
});
```

Use scheduled tasks for nightly syncs, weekly summaries, or any recurring workflow that must complete reliably.

## Concurrency and Queues

Control how many tasks run at the same time with concurrency limits and named queues. This prevents rate-limit errors and keeps resource usage predictable.

<Callout kind="info">
Set per-task and per-queue limits to match external API quotas.
</Callout>

## Trigger.dev Realtime

Trigger.dev Realtime streams task status and custom events directly to your frontend. Connect once and receive updates without polling.

<Tabs>
  <Tab title="React" icon="code">
    Subscribe to runs from any React component.

    ```tsx
    import { useRun } from "@trigger.dev/react";

    function JobStatus({ runId }) {
      const { run } = useRun(runId);
      return <div>Status: {run?.status}</div>;
    }
    ```
  </Tab>
  <Tab title="Vanilla" icon="terminal">
    Use the lightweight client in any browser environment.

    ```ts
    import { runs } from "@trigger.dev/realtime";

    const subscription = runs.subscribe(runId, {
      onUpdate: (run) => console.log(run.status),
    });
    ```
  </Tab>
</Tabs>

## Observability and Tracing

Every task run records inputs, outputs, logs, and spans. The dashboard shows a full trace so you can debug failures quickly.

<Expandable title="What data is captured?" default-open="false">
- Full input and output payloads  
- Console logs and errors  
- External HTTP calls with timing  
- Child task invocations  

</Expandable>

## Examples

<CodeGroup tabs="TypeScript,Python">
```typescript
import { task } from "@trigger.dev/sdk/v3";

export const processOrder = task({
  id: "process-order",
  run: async (payload) => {
    await chargeCustomer(payload.userId);
    await sendConfirmation(payload.email);
  },
});
```

```python
from triggerdev import task

@task(id="process-order")
def process_order(payload):
    charge_customer(payload["userId"])
    send_confirmation(payload["email"])
```
</CodeGroup>

## Best Practices

- Keep task payloads small and store large data in object storage.  
- Set explicit concurrency limits on any task that calls third-party APIs.  
- Use Realtime subscriptions only for runs the current user should see.  
- Review traces regularly to spot slow external calls.
