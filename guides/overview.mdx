## Overview

Vercel gives you a single platform to build, deploy, secure, and operate modern web applications. You push code once, and Vercel handles delivery through automated CI/CD, global content delivery, serverless compute, AI tooling, and security controls. That means you spend less time wiring infrastructure together and more time shipping product value.

Use this page as a starter overview of the platform's main capabilities. It is organized around the services you will most likely evaluate first: CI/CD pipelines, the AI Gateway and AI SDK, Sandbox execution, Workflow orchestration, and Security features.

## CI/CD pipelines

Vercel's CI/CD experience is centered on Git-based workflows. When you push changes, Vercel builds, tests, and deploys automatically. Preview deployments help you validate changes before release, while production deployments move approved code live without manual release steps.

This model works especially well for teams that want consistent delivery across branches and environments. You can treat every pull request as a deployable artifact, which makes review, QA, and stakeholder feedback faster and easier to coordinate.

<CodeGroup tabs="Git push,Bash">
  ```text
Connect a repository to Vercel, then push a branch to create a preview deployment.
```

  ```bash
git add .
git commit -m "Add feature overview"
git push origin main
```

</CodeGroup>

### What to look for

- Fast preview environments for every meaningful change
- Automatic production deploys from the main branch
- A predictable path from commit to release

## AI Gateway and AI SDK

The AI Gateway gives you one endpoint for accessing multiple models. Instead of wiring each provider separately, you route requests through a consistent interface. That simplifies vendor management, request handling, and experimentation.

The AI SDK is the TypeScript toolkit you use to integrate AI features into your app. It helps you build UI and API flows around model responses while keeping your application code focused and readable. Together, the Gateway and SDK help you add AI features without fragmenting your stack.

## Sandbox execution

Sandbox provides isolated code execution for tasks that need safety and separation. You use it when you need to run untrusted or dynamic code with stronger boundaries than a standard application runtime.

This is useful for workflows such as evaluating user-generated snippets, processing agent actions, or running short-lived automation steps. The key idea is simple: you keep execution contained while still letting your product offer flexible capabilities.

<Expandable title="When to use Sandbox" default-open="false">
  Sandbox is a good fit when you need isolation, repeatable execution, and tighter control over runtime side effects.

  Common examples include:

  - Running code generated by an AI agent
  - Evaluating user-submitted scripts
  - Executing temporary automation tasks

</Expandable>

## Workflow orchestration

Workflow orchestration helps you coordinate long-running tasks that do not finish in a single request. You use it to break work into steps, retry safely, and keep track of progress across time.

This matters for product flows that involve background processing, external APIs, or staged approvals. Instead of blocking a user request, you can let a workflow continue in the background and surface results when they are ready.

### Example workflow shape

1. Receive an event or request.
2. Queue the task as a workflow.
3. Run steps in sequence with retries.
4. Store progress and final output.
5. Notify the app when the result is available.

## Security features

Vercel includes security features that help protect your applications at the platform edge. DDoS protection helps absorb malicious traffic, the Web Application Firewall supports granular request filtering, and BotID adds invisible bot detection for user flows that need protection without added friction.

These controls matter when you ship public-facing products that need to stay fast and available. You can layer security into the same delivery platform you already use for deployment, which reduces operational overhead and gives you a more unified setup.

<Callout kind="tip">
Start with the security features that match your highest risk. For many apps, that means bot protection and firewall rules before deeper customization.

</Callout>

## Best practices

Keep your setup simple at first. Start with Git-based deployments, then layer in AI services, workflows, and security as your use case grows. That makes it easier to understand which feature solves which problem.

A good evaluation plan focuses on three questions: how fast you can ship changes, how safely you can add AI capabilities, and how confidently you can protect traffic at the edge. If the platform helps with all three, you have a strong foundation for a production app.

<Expandable title="Evaluation checklist" default-open="false">
  Before you go live, confirm the following:

  - Your repository deploys cleanly from Git
  - Preview deployments match your review process
  - AI requests use the Gateway or SDK intentionally
  - Background jobs use workflows instead of blocking requests
  - Security features are enabled where traffic risk is highest

</Expandable>
