## Overview

PlanetScale gives you a serverless MySQL platform that feels like working with git. You create isolated branches for development, test schema changes safely, and promote them to production with zero downtime. Connection management happens automatically so your applications stay resilient even during traffic spikes.

## Branching and Merging

Branching lets you spin up an isolated copy of your database for any task. Development, testing, and experimentation all happen without touching production data.

- Create a branch from the dashboard or CLI.
- Make changes in isolation.
- Merge approved changes back to the main branch.

<Callout kind="info">
  Every branch runs on dedicated infrastructure so performance tests stay accurate.
</Callout>

## Deploy Requests

Deploy requests turn schema changes into a reviewable workflow. You open a request, see the diff, run checks, and then apply changes safely.

<Tabs>
  <Tab title="Dashboard" icon="monitor">
    Open a deploy request from the branch page, review the schema diff, and click Deploy when ready.
  </Tab>
  <Tab title="CLI" icon="terminal">
    Use the PlanetScale CLI to create and manage deploy requests from your terminal.
  </Tab>
</Tabs>

## Schema Change Safety

PlanetScale runs non-blocking schema changes by default. It detects unsafe operations and blocks them until you confirm.

<CodeGroup tabs="SQL,CLI">
```sql
ALTER TABLE users ADD COLUMN email VARCHAR(255);
```
```bash
pscale deploy-request create main add-email-column
```
</CodeGroup>

## Read Replicas

Add read replicas to scale read-heavy workloads. Replicas stay in sync automatically and you can promote any replica to primary during an outage.

## Insights and Query Monitoring

Query insights surface slow queries, high-cardinality indexes, and connection patterns. Use the data to optimize indexes or rewrite queries before they become problems.

<Expandable title="View sample query insight" default-open="false">
  The dashboard shows execution time, rows examined, and suggested index improvements for each query.
</Expandable>

## Examples

Try these common workflows:

1. Create a development branch.
2. Open a deploy request after testing.
3. Add a read replica for analytics traffic.

## Best Practices

- Keep branches short-lived to reduce storage costs.
- Always review deploy requests with at least one teammate.
- Enable query insights on production branches from day one.
- Use read replicas instead of increasing primary compute for read scaling.
