## Quickstart

Use this quickstart to make your first Vercel API call in under five minutes. You will set up a token, install the SDK, and send a request that either lists deployments or starts a new build.

<Callout kind="info">
You need a Vercel API token before you can call the API. Store it as `VERCEL_TOKEN` in your environment, and never commit it to source control.
</Callout>

### What you will build

You will learn two common request patterns:

- List deployments for a project
- Trigger a new deployment from a build source

You will also see the response shape you can expect from the API so you can plug it into your own tooling right away.

## Prerequisites

Before you start, make sure you have:

- A Vercel account
- An API token with access to deployments
- Node.js installed if you want to use the SDK
- `curl` installed if you want to test the API from the command line

## Set up access

<Steps>
  <Step title="Create an API token" icon="lock">
    Open your Vercel account settings, create a token, and copy it to a safe place.

    Use the token value as `VERCEL_TOKEN` in your shell environment.

  </Step>
  <Step title="Set the environment variable" icon="settings">
    Export the token so your local tools can read it.

    ```bash
    export VERCEL_TOKEN="YOUR_API_TOKEN"
    ```

  </Step>
  <Step title="Choose a project identifier" icon="database">
    Pick the project ID or name you want to query or deploy.

    If you are not sure which one to use, start with the project you already manage in Vercel.

  </Step>
</Steps>

## Make your first request

Use the API endpoint to list deployments for a project. The same authentication pattern works for other deployment actions.

<CodeGroup tabs="cURL,JavaScript">
  ```bash
  curl -s https://api.example.com/v1/deployments \
    -H "Authorization: Bearer $VERCEL_TOKEN" \
    -H "Content-Type: application/json"
  ```

  ```javascript
  const token = process.env.VERCEL_TOKEN;

  const response = await fetch("https://api.example.com/v1/deployments", {
    headers: {
      Authorization: `Bearer ${token}`,
      "Content-Type": "application/json",
    },
  });

  const data = await response.json();
  console.log(data);
  ```
</CodeGroup>

The response is JSON. For a successful call, you typically get a list of deployment objects with identifiers, names, states, and URLs.

```json
{
  "deployments": [
    {
      "id": "dpl_123",
      "name": "my-app",
      "state": "READY",
      "url": "https://my-app.example.com"
    }
  ]
}
```

## Trigger a build

If you want to create a new deployment instead of listing existing ones, send a request to the build endpoint with the project reference.

<CodeGroup tabs="cURL,JavaScript">
  ```bash
  curl -s https://api.example.com/v1/deployments \
    -X POST \
    -H "Authorization: Bearer $VERCEL_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "projectId": "prj_123",
      "target": "production"
    }'
  ```

  ```javascript
  const token = process.env.VERCEL_TOKEN;

  const response = await fetch("https://api.example.com/v1/deployments", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${token}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      projectId: "prj_123",
      target: "production",
    }),
  });

  const data = await response.json();
  console.log(data);
  ```
</CodeGroup>

A successful trigger returns a deployment record and a status that tells you the build has started.

```json
{
  "deployment": {
    "id": "dpl_456",
    "state": "BUILDING",
    "url": "https://my-app-git-main.example.com"
  }
}
```

## Response formats

Use these fields to recognize the most common response shapes.

| Scenario | Status | Shape |
| --- | --- | --- |
| List deployments | `200 OK` | `{ deployments: Deployment[] }` |
| Trigger build | `201 Created` | `{ deployment: Deployment }` |
| Invalid token | `401 Unauthorized` | `{ error: string }` |
| Missing project | `404 Not Found` | `{ error: string }` |

### Deployment object

A deployment object usually includes the following fields:

| Field | Type | Notes |
| --- | --- | --- |
| `id` | string | Unique deployment identifier |
| `name` | string | Project name |
| `state` | string | Current lifecycle state |
| `url` | string | Public deployment URL |
