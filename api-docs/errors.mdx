## Payment Failure Codes

Payment failures occur when the checkout flow rejects a transaction. Each failure returns a specific code in the response body.

<Expandable title="PAYMENT_001: Card issuer rejection" default-open="false">

**Problem**

The API returns `{"error":"PAYMENT_001","message":"Card issuer rejected transaction"}` during checkout completion.

**Cause**

The card network declined the authorization request. This typically follows from insufficient funds, mismatched billing address, or regional restrictions on the card.

**Fix**

Capture the decline reason from the `details` field in the response. Retry with an alternate payment method or prompt the customer to contact their issuer. Verify that the `{PAYMENT_KEY}` value matches the merchant account configuration.

```bash
curl -X POST https://api.example.com/v1/checkout \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"cart_token":"abc123","payment_key":"pk_live_xxx"}'
```

</Expandable>

<Expandable title="PAYMENT_002: CVV mismatch" default-open="false">

**Problem**

Checkout fails with `{"error":"PAYMENT_002","message":"CVV verification failed"}`.

**Cause**

The supplied CVV does not match the value on file with the card issuer.

**Fix**

Re-collect the CVV from the customer and resubmit the payment object. Ensure the request includes the correct `cvv` parameter under the payment details.

</Expandable>

## Token Validation Errors

Token errors prevent cart operations when authentication values are invalid.

<Expandable title="TOKEN_100: Invalid cart token" default-open="false">

**Problem**

Requests return `{"error":"TOKEN_100","message":"Cart token is malformed or expired"}`.

**Cause**

The `CART_TOKEN` value is either expired, already consumed, or contains invalid characters.

**Fix**

Generate a fresh token by calling the cart creation endpoint. Store the new token and include it in subsequent requests.

```javascript
const response = await fetch('https://api.example.com/v1/cart', {
  method: 'POST',
  headers: { 'Authorization': 'Bearer YOUR_API_KEY' }
});
const { cart_token } = await response.json();
```

</Expandable>

<Expandable title="TOKEN_101: Payment key mismatch" default-open="false">

**Problem**

The server replies `{"error":"TOKEN_101","message":"Payment key does not match cart merchant"}`.

**Cause**

The supplied `{PAYMENT_KEY}` belongs to a different merchant account than the one that created the cart.

**Fix**

Confirm both keys originate from the same ShopifyMax merchant dashboard. Replace the key in the request payload and retry.

</Expandable>

## Catalog Limit Responses

Catalog operations return specific limits when product counts exceed platform thresholds.

<Expandable title="CATALOG_200: Product count exceeded" default-open="false">

**Problem**

Bulk import fails with `{"error":"CATALOG_200","message":"Catalog exceeds 100000 products"}`.

**Cause**

The merchant attempted to add products beyond the supported catalog size.

**Fix**

Remove inactive products or split the catalog across multiple ShopifyMax stores. Use the delete endpoint to prune entries before retrying the import.

```bash
curl -X DELETE https://api.example.com/v1/products/12345 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

</Expandable>
