## HTTP Status Codes

PlanetScale returns standard HTTP status codes. The table below summarizes the most common responses from the API.

| Status | Meaning                  | Typical Cause                     |
| ------ | ------------------------ | --------------------------------- |
| 400    | Bad Request              | Invalid parameters or payload     |
| 401    | Unauthorized             | Missing or invalid API token      |
| 403    | Forbidden                | Branch protection rule violation  |
| 409    | Conflict                 | Schema deployment failure         |
| 429    | Too Many Requests        | Rate limit exceeded               |

Examine the `error` object in the response body for a machine-readable code and human-readable message.

```json
{
  "error": {
    "code": "branch_protected",
    "message": "Cannot delete branch 'main' because it is protected."
  }
}
```

## Branch Protection Errors

<Expandable title="403 branch_protected when deleting a branch" default-open="false">

**Problem**

```
DELETE /v1/organizations/my-org/databases/prod/branches/main
403 Forbidden
{"error":{"code":"branch_protected","message":"Cannot delete branch 'main' because it is protected."}}
```

**Cause**

The branch has a protection rule that prevents deletion or direct writes.

**Fix**

Remove the protection rule first:

```bash
curl -X PATCH \
  https://api.example.com/v1/organizations/my-org/databases/prod/branches/main \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"protected": false}'
```

Then retry the delete operation.

</Expandable>

<Expandable title="403 branch_protected on direct schema change" default-open="false">

**Problem**

```
POST /v1/organizations/my-org/databases/prod/branches/main/schema
403 Forbidden
{"error":{"code":"branch_protected","message":"Direct schema changes are not allowed on protected branches."}}
```

**Cause**

The request targets a protected branch such as `main`.

**Fix**

Create a development branch, apply the change there, then open a deploy request.

</Expandable>

## Schema Deployment Failures

<Expandable title="409 schema_conflict during deploy request" default-open="false">

**Problem**

```
POST /v1/organizations/my-org/databases/prod/deploy-requests/42/deploy
409 Conflict
{"error":{"code":"schema_conflict","message":"Deployment blocked: column 'email' already exists on table 'users'."}}
```

**Cause**

The schema change in the deploy request conflicts with the current state of the production branch.

**Fix**

1. Pull the latest schema from the production branch into your development branch.
2. Resolve the conflict locally.
3. Push the corrected schema and update the deploy request.

```bash
pscale branch create prod fix-conflict --from main
pscale deploy-request create prod fix-conflict
```

</Expandable>

<Expandable title="409 pending_migrations when deploying" default-open="false">

**Problem**

```
{"error":{"code":"pending_migrations","message":"Branch contains unapplied migrations. Apply or discard them before deploying."}}
```

**Cause**

Unapplied migration files remain on the development branch.

**Fix**

Apply the migrations on the development branch, then retry the deploy request.

```bash
pscale shell prod fix-conflict < migrations/20241001120000_add_email.sql
```

</Expandable>
