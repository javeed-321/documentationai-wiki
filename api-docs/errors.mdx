## Common Error Codes

Twilio returns standard HTTP status codes along with a numeric error code in the response body. Each code maps to a specific failure condition during request validation or delivery.

## Invalid Number Errors

<Expandable title="21211: Invalid 'To' Phone Number" default-open="false">

**Problem**

The request fails with HTTP 400 and the body contains:

```json
{
  "code": 21211,
  "message": "The 'To' number +15551234567 is not a valid phone number.",
  "status": 400
}
```

**Cause**

The value supplied in the `To` parameter does not match E.164 format or is not a number that can receive the requested channel.

**Fix**

Format the number with a leading `+` and country code. Validate the number before the request:

```bash
curl -X POST https://api.twilio.com/2010-04-01/Accounts/ACxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx/Messages.json \
  --data-urlencode "To=+15551234567" \
  --data-urlencode "From=+15559876543" \
  --data-urlencode "Body=Test" \
  -u ACxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx:your_auth_token
```

</Expandable>

<Expandable title="20003: Authenticate" default-open="false">

**Problem**

The request returns HTTP 401 with:

```json
{
  "code": 20003,
  "message": "Authenticate",
  "status": 401
}
```

**Cause**

The request did not include a valid Account SID and Auth Token pair in the `Authorization` header.

**Fix**

Use HTTP Basic Auth with your Account SID as the username and Auth Token as the password. Example:

```bash
curl -X GET https://api.twilio.com/2010-04-01/Accounts/ACxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.json \
  -u ACxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx:your_auth_token
```

Store the token in an environment variable and never commit it to source control.

</Expandable>

## Rate Limiting

<Expandable title="429: Too Many Requests" default-open="false">

**Problem**

Repeated requests return HTTP 429 and the header `X-Rate-Limit-Remaining: 0`.

**Cause**

The account exceeded the allowed request rate for the endpoint.

**Fix**

Implement exponential backoff. Wait at least the number of seconds indicated by the `Retry-After` header before retrying:

```python
import time
import requests

def send_with_backoff(url, payload, token):
    delay = 1
    while True:
        resp = requests.post(url, data=payload, auth=token)
        if resp.status_code != 429:
            return resp
        time.sleep(delay)
        delay = min(delay * 2, 60)
```

</Expandable>

## Webhook Failures

<Expandable title="Webhook Delivery Failures" default-open="false">

**Problem**

Status callbacks never arrive or Twilio logs show repeated 4xx/5xx responses from your endpoint.

**Cause**

Your webhook URL returns a non-2xx status, times out after 15 seconds, or rejects the request due to TLS or authentication issues.

**Fix**

Ensure the endpoint responds with HTTP 200 within 15 seconds and uses a publicly reachable HTTPS URL. Test the endpoint with:

```bash
curl -X POST https://your-webhook.example.com/twilio \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "CallSid=CAxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx&CallStatus=completed"
```

Check the Twilio Console under the specific resource's "Webhooks & Email" logs for the exact failure reason.

</Expandable>
