## Common Error Codes

Twilio returns numeric error codes in the response body when a request fails. Each code maps to a specific validation or delivery issue.

<Callout kind="info">
Review the `code` and `message` fields together to identify the exact failure point.
</Callout>

<ExpandableGroup>
<Expandable title="Error 21211: Invalid To phone number" default-open="false">

**Problem**

A request to send an SMS or make a voice call fails with code 21211.

**Cause**

The value supplied for the `To` parameter is not a valid E.164-formatted phone number or does not exist in your account's geography permissions.

**Fix**

Verify the number format and resend.

```json
{
  "code": 21211,
  "message": "The 'To' number 415-555-1234 is not a valid phone number.",
  "status": 400
}
```

Update the request to use the correct format.

```bash
curl -X POST https://api.example.com/2010-04-01/Accounts/ACxxx/Messages.json \
  -d "To=+14155551234" \
  -d "From=+14155556789" \
  -d "Body=Hello" \
  -u "ACxxx:YOUR_API_KEY"
```
</Expandable>

<Expandable title="Error 21606: The From number is not a valid Twilio number" default-open="false">

**Problem**

Outbound messaging or voice requests return code 21606.

**Cause**

The `From` parameter references a phone number or messaging service SID that is not owned by the authenticated account or is not enabled for the requested channel.

**Fix**

Confirm the number belongs to the account and has the required capabilities.

```json
{
  "code": 21606,
  "message": "The From number +14155556789 is not a valid Twilio number for this account.",
  "status": 400
}
```

Replace the `From` value with a verified Twilio number or messaging service SID.

```bash
curl -X POST https://api.example.com/2010-04-01/Accounts/ACxxx/Messages.json \
  -d "To=+14155551234" \
  -d "From=MGxxx" \
  -d "Body=Hello" \
  -u "ACxxx:YOUR_API_KEY"
```
</Expandable>
</ExpandableGroup>

## Interpreting 4xx and 5xx Responses

4xx status codes indicate client errors that you can correct by changing the request payload or headers. 5xx codes signal server-side issues; retry the request after a short delay.

- 400 Bad Request: malformed parameters or invalid values.
- 401 Unauthorized: missing or incorrect API credentials.
- 429 Too Many Requests: rate limit exceeded.
- 500 Internal Server Error: temporary Twilio platform issue.

## Request Validation and Debugging

Use the following workflow to validate requests before they reach production.

<Steps>
<Step title="Validate parameters" icon="check-circle">

Pass every required field and confirm data types match the API reference.

</Step>
<Step title="Inspect response body" icon="terminal">

Every error response contains `code`, `message`, and `more_info` fields.

```json
{
  "code": 21211,
  "message": "...",
  "more_info": "https://www.twilio.com/docs/errors/21211"
}
```
</Step>
<Step title="Check logs" icon="book-open">

Query the Twilio Console logs or the /Notifications endpoint for the request SID.

</Step>
</Steps>
