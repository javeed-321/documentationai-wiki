## Overview

Stripe returns machine-readable error codes in JSON responses. Inspect the `type` and `code` fields to determine the exact failure and apply the correct remediation.

## Card Decline Errors

<Expandable title="card_declined with insufficient_funds">
Problem:  
A charge request returns HTTP 402 with `"code": "card_declined"` and `"decline_code": "insufficient_funds"`.

Cause:  
The customer's card has insufficient available balance for the attempted amount.

Fix:  
Advise the customer to use a different card or reduce the charge amount. You can surface the `decline_code` value directly to the customer.

```json
{
  "error": {
    "type": "card_error",
    "code": "card_declined",
    "decline_code": "insufficient_funds",
    "message": "Your card has insufficient funds."
  }
}
```

</Expandable>

<Expandable title="card_declined with do_not_honor">
Problem:  
Charge fails with `"decline_code": "do_not_honor"`.

Cause:  
The issuing bank declined the transaction without providing a more specific reason.

Fix:  
Ask the customer to contact their bank or try another card. Do not retry the same card immediately.

</Expandable>

## API Authentication Errors

<Expandable title="Invalid API key">
Problem:  
Requests return HTTP 401 with `"type": "invalid_request_error"` and message containing `"Invalid API Key"`.

Cause:  
The `Authorization` header contains an unknown or revoked secret key.

Fix:  
Verify that you are using the correct secret key from the Developers section of the Stripe dashboard and that the key has not been deleted.

```bash
curl https://api.stripe.com/v1/charges \
  -u sk_test_your_key_here:
```

</Expandable>

## Idempotency Errors

<Expandable title="idempotency_key_in_use">
Problem:  
A POST returns HTTP 409 with `"code": "idempotency_key_in_use"`.

Cause:  
The same idempotency key is already attached to an in-progress request.

Fix:  
Wait for the original request to complete, then retry with the same key or generate a new key for a new operation.

</Expandable>

## Rate Limiting and Retries

<Expandable title="Rate limit exceeded">
Problem:  
HTTP 429 response with `"type": "rate_limit_error"`.

Cause:  
Too many requests were sent in a short time window.

Fix:  
Implement exponential backoff. Respect the `Retry-After` header when present.

```python
import time
import requests

def retry_request(url, headers, data, max_retries=5):
    for attempt in range(max_retries):
        response = requests.post(url, headers=headers, json=data)
        if response.status_code != 429:
            return response
        time.sleep(2 ** attempt)
    raise Exception("Max retries exceeded")
```

</Expandable>

<Callout kind="info">
Always log the full error object returned by Stripe. The combination of `type`, `code`, and `decline_code` provides the precise information needed for automated handling.
</Callout>
