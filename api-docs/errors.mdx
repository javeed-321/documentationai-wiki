## HTTP Status Codes

ShopifyMax returns standard HTTP status codes for API requests. Inspect the response body for a JSON object containing an `errors` array with precise messages.

<Callout kind="info">
Inspect the `X-Request-Id` header on every response when opening a support ticket.
</Callout>

## Rate Limiting

ShopifyMax enforces a limit of 2 requests per second per shop. Exceeding the limit returns a 429 response.

<Expandable title="429 Too Many Requests">
Problem: API calls return HTTP 429 with the message `Rate limit exceeded. Retry after 1s`.

Cause: Your client issued more than two requests in the same second to the same shop.

Fix: Implement exponential backoff. The example below shows a minimal retry loop.

```javascript
async function callWithBackoff(url, options, retries = 3) {
  const res = await fetch(url, options);
  if (res.status === 429 && retries > 0) {
    await new Promise(r => setTimeout(r, 1000));
    return callWithBackoff(url, options, retries - 1);
  }
  return res;
}
```

</Expandable>

## Webhook Failures

Webhooks for order and inventory events must return a 2xx status within five seconds. Failures are logged under the shop's webhook history.

<Expandable title="Webhook delivery failed with 5xx">
Problem: The webhook endpoint returns 500 and ShopifyMax stops delivering subsequent events.

Cause: Your handler threw an uncaught exception while processing the payload.

Fix: Wrap your handler in a try/catch and always respond with 200 before performing long-running work.

```javascript
app.post('/webhooks/orders', (req, res) => {
  res.status(200).send('OK');
  processOrderAsync(req.body).catch(console.error);
});
```

</Expandable>

## Checkout and Inventory Errors

Checkout and inventory endpoints return 422 when the requested change cannot be applied.

<Expandable title="422 Unprocessable Entity on checkout">
Problem: `PUT /checkouts/{token}` returns 422 with `inventory_item out of stock`.

Cause: The variant quantity in the cart exceeds available inventory at the moment of update.

Fix: Re-fetch current inventory levels before submitting the final checkout and surface the error to the customer.

```javascript
const inv = await fetch('https://api.example.com/inventory_levels.json');
const stock = await inv.json();
if (stock.available < cartQty) {
  throw new Error('Selected quantity exceeds stock');
}
```

</Expandable>

<Expandable title="Inventory adjustment rejected">
Problem: `POST /inventory_levels/adjust` returns 422 with `adjustment would result in negative quantity`.

Cause: The adjustment value would bring the location below zero.

Fix: Query the current quantity first, then calculate a safe delta.

```javascript
const current = await getCurrentQuantity(locationId, itemId);
const safeDelta = Math.max(delta, -current);
await adjustInventory(locationId, itemId, safeDelta);
```

</Expandable>
