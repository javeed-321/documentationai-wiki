## Authentication and Permission Errors

Twilio returns HTTP 401 or 403 responses when credentials are missing or lack required scopes. Check the `WWW-Authenticate` header for the exact reason.

<Expandable title="20003 Authentication Error" default-open="false">

**Problem**

Requests return status 401 with body:

```json
{
  "code": 20003,
  "message": "Authenticate",
  "more_info": "https://www.twilio.com/docs/errors/20003",
  "status": 401
}
```

**Cause**

The `Authorization` header contains an invalid Account SID and Auth Token pair, or the token has expired.

**Fix**

Replace the credentials in your request. Example using curl:

```bash
curl -X POST https://api.example.com/2010-04-01/Accounts/ACxxxxxxxx/Messages.json \
  -u "ACxxxxxxxx:your_auth_token"
```

Regenerate the Auth Token in the Twilio Console if the current token is revoked.

</Expandable>

<Expandable title="20404 Permission Denied" default-open="false">

**Problem**

Status 403 response:

```json
{
  "code": 20404,
  "message": "The requested resource does not exist",
  "status": 403
}
```

**Cause**

The API key lacks the `voice` or `sms` scope required for the endpoint.

**Fix**

Create a new API key with the correct scopes and update the request:

```bash
curl -X GET https://api.example.com/2010-04-01/Accounts/ACxxxxxxxx/Calls.json \
  -u "SKxxxxxxxx:your_api_secret"
```

</Expandable>

## Rate Limiting and Invalid Parameters

Twilio enforces per-second and daily limits. Exceeding them produces 429 responses. Invalid request bodies produce 400 responses with field-level details.

<Expandable title="20429 Too Many Requests" default-open="false">

**Problem**

```json
{
  "code": 20429,
  "message": "Too Many Requests",
  "status": 429
}
```

**Cause**

More than 100 requests per second to the same endpoint from one IP.

**Fix**

Implement exponential backoff. Example in a retry loop:

```javascript
const delay = Math.pow(2, attempt) * 100;
await new Promise(resolve => setTimeout(resolve, delay));
```

Reduce concurrent connections or request a rate limit increase.

</Expandable>

<Expandable title="21211 Invalid Phone Number" default-open="false">

**Problem**

```json
{
  "code": 21211,
  "message": "The 'To' number is not a valid phone number.",
  "status": 400
}
```

**Cause**

The `To` parameter contains a non-E.164 number or an unsupported country code.

**Fix**

Format numbers as `+15551234567` and verify the number is enabled for the destination country in your account settings.

</Expandable>

## Webhook and Callback Failures

Twilio retries failed status callbacks up to three times. Persistent failures appear in the request inspector with specific error codes.

<Expandable title="11200 HTTP Callback Failure" default-open="false">

**Problem**

Webhook logs show:

```
Error Code: 11200
Description: HTTP retrieval failure
```

**Cause**

Your server returns a non-2xx status or times out after 15 seconds.

**Fix**

Ensure the endpoint responds with 200 within five seconds. Add basic authentication validation:

```javascript
app.post("/status", (req, res) => {
  if (req.headers.authorization !== "Basic ...") {
    return res.status(401).send("Unauthorized");
  }
  res.status(200).send("OK");
});
```

</Expandable>

<Expandable title="21610 SMS Delivery Failure" default-open="false">

**Problem**

Status callback contains:

```json
{
  "error_code": 21610,
  "error_message": "Message cannot be sent to an unverified number."
}
```

**Cause**

The destination number is not verified in trial accounts.

**Fix**

Verify the number in the Console or upgrade the account to remove verification requirements.

</Expandable>
