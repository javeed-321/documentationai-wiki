## Task Execution Errors

Use these patterns to diagnose failures that occur while a task runs.

<Expandable title="Task failed after 3 retries: ECONNRESET" default-open="false">

Problem: Your task exits with the message `Task failed after 3 retries: ECONNRESET`.

Cause: An outbound HTTP call to an external service dropped the connection before Trigger.dev received a response.

Fix: Wrap the call in a retry block and increase the timeout.

```typescript
import { task } from "@trigger.dev/sdk";

export const myTask = task({
  id: "fetch-data",
  retry: { maxAttempts: 5, factor: 2 },
  run: async (payload) => {
    const res = await fetch("https://api.example.com/data", {
      signal: AbortSignal.timeout(30000),
    });
    return res.json();
  },
});
```

</Expandable>

<Expandable title="ValidationError: payload must contain id" default-open="false">

Problem: The run log shows `ValidationError: payload must contain id`.

Cause: The JSON you sent to `triggerTask` does not match the Zod schema defined on the task.

Fix: Add the missing field before you call the task.

```typescript
await client.triggerTask("process-user", {
  payload: { id: "user_123", email: "user@example.com" },
});
```

</Expandable>

## Retry and Queue Failures

These errors appear when Trigger.dev cannot place a task onto a queue or when all retry attempts are exhausted.

<Expandable title="QueueError: concurrency limit reached" default-open="false">

Problem: You receive `QueueError: concurrency limit reached for queue "default"`.

Cause: The queue already holds the maximum number of concurrent runs allowed by your project settings.

Fix: Increase the concurrency setting or create a dedicated queue for the task.

```typescript
export const heavyTask = task({
  id: "heavy-work",
  queue: { concurrencyLimit: 10 },
  run: async (payload) => { ... },
});
```

</Expandable>

<Expandable title="Task timed out after 300000ms" default-open="false">

Problem: The run ends with `Task timed out after 300000ms`.

Cause: A long-running operation exceeded the 5-minute default timeout.

Fix: Split the work into smaller subtasks or raise the timeout value.

```typescript
export const longTask = task({
  id: "long-job",
  timeout: 1800000, // 30 minutes
  run: async (payload) => { ... },
});
```

</Expandable>

## Rate Limiting Responses

Trigger.dev returns standard HTTP status codes when you exceed API limits.

<Expandable title="429 Too Many Requests" default-open="false">

Problem: The client receives HTTP 429 with body `{"error":"rate_limit_exceeded"}`.

Cause: You sent more than 100 requests per minute to the Trigger.dev API from a single token.

Fix: Add exponential backoff to your client code.

```typescript
async function triggerWithBackoff(payload) {
  for (let attempt = 0; attempt < 5; attempt++) {
    const res = await fetch("https://api.example.com/trigger", {
      method: "POST",
      headers: { Authorization: `Bearer ${process.env.TRIGGER_API_KEY}` },
      body: JSON.stringify(payload),
    });
    if (res.status !== 429) return res.json();
    await new Promise((r) => setTimeout(r, 1000 * Math.pow(2, attempt)));
  }
  throw new Error("Rate limit exceeded after retries");
}
```

</Expandable>

<Callout kind="info">
Inspect the `x-ratelimit-remaining` response header to know how many requests you have left in the current window.
</Callout>
