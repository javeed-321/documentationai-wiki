## Overview

The PlanetScale API requires authentication on every request. You can authenticate with service tokens for automated access or OAuth for user-authorized flows. Service tokens are long-lived credentials scoped to an organization.

## Authentication methods

<Tabs>
  <Tab title="Service tokens" icon="key">
    Service tokens grant access to one organization. Create them in the dashboard under Organization settings. Each token consists of an ID and a secret that you must store securely.

    <ParamField body="service_token_id" param-type="string" required="true">
      The identifier portion of the token.
    </ParamField>

    <ParamField body="service_token" param-type="string" required="true">
      The secret portion of the token.
    </ParamField>
  </Tab>
  <Tab title="OAuth" icon="lock">
    OAuth flows let applications act on behalf of a user. Register your application in the PlanetScale dashboard to obtain a client ID and secret, then follow the standard authorization code flow.
  </Tab>
</Tabs>

## Making authenticated requests

Include credentials in the Authorization header. The examples below show both service token and OAuth usage across languages.

<CodeGroup tabs="cURL,JavaScript,Python">
```bash
curl -H "Authorization: Bearer pscale_token_123:secret_abc" \
  https://api.example.com/v1/organizations/my-org/databases
```

```javascript
const response = await fetch(
  "https://api.example.com/v1/organizations/my-org/databases",
  {
    headers: {
      Authorization: "Bearer pscale_token_123:secret_abc",
    },
  }
);
```

```python
import requests

headers = {"Authorization": "Bearer pscale_token_123:secret_abc"}
response = requests.get(
    "https://api.example.com/v1/organizations/my-org/databases",
    headers=headers,
)
```
</CodeGroup>

## Security considerations

<Callout kind="alert">
Store token secrets only in secure environment variables or a secrets manager. Rotate tokens regularly and revoke them immediately if compromised. Never embed secrets in client-side code or public repositories.
</Callout>
