## Overview

Vercel API requests require authentication through either personal access tokens or OAuth 2.0 flows. Access tokens grant direct access scoped to your account. OAuth 2.0 enables third-party applications to act on behalf of users with explicit consent.

All authenticated requests must include the token in the Authorization header. Tokens remain valid until revoked through the dashboard or API.

## Authentication Methods

<Tabs>
  <Tab title="Access Tokens" icon="key">
    Create access tokens in the Vercel dashboard under Settings. Each token supports specific scopes that limit its permissions.

    <ParamField header="Authorization" param-type="string" required="true">
      Bearer token in the format `Bearer YOUR_ACCESS_TOKEN`.
    </ParamField>
  </Tab>
  <Tab title="OAuth 2.0" icon="shield">
    Register your application to obtain client credentials. Users authorize your app through the standard OAuth authorization code flow.

    Redirect users to `https://api.example.com/oauth/authorize` with your client ID and requested scopes.
  </Tab>
</Tabs>

## Creating Access Tokens

Generate tokens via the dashboard or the tokens endpoint. Specify scopes during creation to restrict access.

Supported scopes include `deployment:read`, `deployment:write`, `project:read`, and `domain:write`.

## Making Authenticated Requests

Include the token in every request header.

<CodeGroup tabs="JavaScript,Python,cURL">
```javascript
const response = await fetch('https://api.example.com/v2/deployments', {
  headers: {
    Authorization: 'Bearer YOUR_ACCESS_TOKEN',
  },
});
```
```python
import requests

response = requests.get(
    'https://api.example.com/v2/deployments',
    headers={'Authorization': 'Bearer YOUR_ACCESS_TOKEN'}
)
```
```bash
curl -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  https://api.example.com/v2/deployments
```
</CodeGroup>

## Security Best Practices

<Callout kind="alert">
  Store tokens in environment variables or secure secret managers. Never commit tokens to source control or expose them in client-side code. Rotate tokens regularly and revoke unused ones immediately.
</Callout>

Use the minimum required scopes for each token. Monitor token usage through the dashboard audit logs.
