## Overview

ShopifyMax uses OAuth 2.0 for delegated access and project-specific API tokens for server-to-server requests. You use OAuth when a user or workspace authorizes access, and you use project tokens when your backend needs to call the API without an interactive login.

Authentication is scoped to a project. Each access token carries only the permissions granted for that project, so you should request the narrowest scopes that match the endpoints you call. If a token is compromised, you can rotate it without changing the entire integration.

The example domain shown in this documentation is for reference only.

<Callout kind="info">

Use `https://api.example.com` in examples and replace placeholder values with your own project credentials.

</Callout>

### Authentication methods

<Tabs>
  <Tab title="OAuth 2.0" icon="lock">

    Use OAuth 2.0 when a user or administrator connects ShopifyMax to your application. The authorization server issues an authorization code, which you exchange for an access token and a refresh token.

    OAuth is the right choice when you need:

    - User consent
    - Delegated access
    - Short-lived access tokens
    - Refresh token rotation

  </Tab>
  <Tab title="Project token" icon="key">

    Use a project-specific API token for backend jobs, webhooks, and internal services. Project tokens are issued for a single project and should never be exposed in client-side code.

    Project tokens are the right choice when you need:

    - Server-to-server access
    - Non-interactive requests
    - Stable automation credentials
    - Simple token revocation

  </Tab>
  <Tab title="Scoped permissions" icon="shield">

    ShopifyMax enforces scoped permissions at token issuance time and request time. A token can only access resources that match its granted scopes.

    Common scope examples include:

    - `projects.read`
    - `projects.write`
    - `brands.read`
    - `assets.write`

  </Tab>
</Tabs>

## Implementation

Use the authorization code flow for user-facing integrations. Your application redirects the user to the authorization endpoint, receives a temporary code, and exchanges that code for tokens on your server.

For backend automation, send the project token in the `Authorization` header. Keep the token in a secure secret store and load it at runtime.

<Steps>
  <Step title="Request authorization" icon="arrow-right">

    Redirect the user to the authorization endpoint with your client ID, requested scopes, and redirect URI.

    ```text
    https://api.example.com/oauth/authorize?response_type=code&client_id=YOUR_CLIENT_ID&redirect_uri=https%3A%2F%2Fdashboard.example.com%2Fauth%2Fcallback&scope=projects.read%20projects.write
    ```

  </Step>
  <Step title="Exchange the code" icon="settings">

    Send the authorization code to your server and exchange it for an access token.

    <CodeGroup tabs="cURL,JavaScript,Python">
      ```bash
      curl -X POST https://api.example.com/oauth/token \
        -H "Content-Type: application/json" \
        -d '{
          "grant_type": "authorization_code",
          "client_id": "YOUR_CLIENT_ID",
          "client_secret": "YOUR_CLIENT_SECRET",
          "code": "YOUR_AUTHORIZATION_CODE",
          "redirect_uri": "https://dashboard.example.com/auth/callback"
        }'
      ```
      ```javascript
      const response = await fetch("https://api.example.com/oauth/token", {
        method: "POST",
        headers: {
          "Content-Type": "application/json",
        },
        body: JSON.stringify({
          grant_type: "authorization_code",
          client_id: "YOUR_CLIENT_ID",
          client_secret: "YOUR_CLIENT_SECRET",
          code: "YOUR_AUTHORIZATION_CODE",
          redirect_uri: "https://dashboard.example.com/auth/callback",
        }),
      });

      const data = await response.json();
      ```
      ```python
      import requests

      response = requests.post(
          "https://api.example.com/oauth/token",
          json={
              "grant_type": "authorization_code",
              "client_id": "YOUR_CLIENT_ID",
              "client_secret": "YOUR_CLIENT_SECRET",
              "code": "YOUR_AUTHORIZATION_CODE",
              "redirect_uri": "https://dashboard.example.com/auth/callback",
          },
      )

      data = response.json()
      ```
    </CodeGroup>

  </Step>
  <Step title="Send authenticated requests" icon="zap">

    Include the access token in the `Authorization` header for every API request.

    ```http
    Authorization: Bearer YOUR_ACCESS_TOKEN
    ```

  </Step>
</Steps>

### Request fields

<ParamField query="client_id" param-type="string" required="true">
  Your OAuth client identifier.
</ParamField>

<ParamField query="redirect_uri" param-type="string" required="true">
  The exact callback URL registered for your application.
</ParamField>

<ParamField query="scope" param-type="string" required="true">
  Space-separated list of requested permissions.
</ParamField>

<ParamField header="Authorization" param-type="string" required="true">
  Bearer token used to authorize API requests.
</ParamField>

### Token response fields

<ResponseField name="access_token" field-type="string" required="true">
  Short-lived token used for API requests.
</ResponseField>

<ResponseField name="refresh_token" field-type="string" required="true">
  Long-lived token used to request a new access token.
</ResponseField>

<ResponseField name="expires_in" field-type="integer" required="true">
  Token lifetime in seconds.
</ResponseField>

<ResponseField name="scope" field-type="string" required="true">
  Permissions granted to the token.
</ResponseField>

## Security tips

Rotate tokens regularly and revoke any token that is no longer needed. Do not hardcode credentials in client code, browser bundles, or public repositories. Store secrets in your infrastructure secret manager and inject them at deploy time.

<Callout kind="alert">

Never send `client_secret`, refresh tokens, or project tokens from the browser. Keep all token exchanges on the server, and treat every token as sensitive.

</Callout>

### Token rotation checklist

1. Create a new token with the same scopes as the token you want to replace.
2. Update your servers to use the new token.
3. Verify requests succeed with the new token.
4. Revoke the old token.
5. Audit logs for unexpected authentication failures.

### Common mistakes

- Requesting scopes you do not need
- Reusing the same token across unrelated projects
- Logging tokens in application or access logs
- Storing refresh tokens in browser storage
- Skipping revocation after a credential leak
