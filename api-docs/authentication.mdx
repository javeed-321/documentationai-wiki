## Overview

Vercel API requests require authentication via personal access tokens or OAuth2 flows. Include the token in the Authorization header for every call. Tokens grant access based on assigned scopes that control which resources and actions are permitted.

## Authentication Methods

<Tabs>
<Tab title="Personal Access Tokens" icon="key">

Create a personal access token from the account settings page. This token authenticates requests on your behalf.

<ParamField header="Authorization" param-type="string" required="true">
  Use the format `Bearer <token>`. Replace `<token>` with your personal access token.
</ParamField>

</Tab>
<Tab title="OAuth2" icon="shield">

Register an OAuth application to obtain client credentials. Users authorize your application to receive scoped access tokens.

<ParamField body="client_id" param-type="string" required="true">
  The client identifier issued when you registered the OAuth application.
</ParamField>

<ParamField body="client_secret" param-type="string" required="true">
  The client secret issued when you registered the OAuth application.
</ParamField>

</Tab>
</Tabs>

## Implementation

Use the Authorization header in every request. The examples below demonstrate token usage across languages.

<CodeGroup tabs="cURL,JavaScript,Python">
```bash
curl -H "Authorization: Bearer YOUR_TOKEN" \
  https://api.example.com/v1/deployments
```
```javascript
const response = await fetch('https://api.example.com/v1/deployments', {
  headers: {
    Authorization: 'Bearer YOUR_TOKEN',
  },
});
```
```python
import requests

headers = {'Authorization': 'Bearer YOUR_TOKEN'}
response = requests.get('https://api.example.com/v1/deployments', headers=headers)
```
</CodeGroup>

## Security Considerations

<Callout kind="alert">
  Store tokens securely and rotate them regularly. Never commit tokens to source control or expose them in client-side code. Limit token scopes to the minimum permissions required for your use case.
</Callout>
